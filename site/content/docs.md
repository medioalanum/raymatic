<h1>Build a publication, not a publishing system.</h1>
<p>Raymatic v0.1.0 is a convention-first static publisher. This guide documents the behavior that exists today across the source project, CI, and release workflow.</p>

<h2 id="getting-started">Getting started</h2>
<pre>$ ray new my-site
$ cd my-site
$ ray dev
Preview available at http://127.0.0.1:3000</pre>
<p>Open the preview in a browser. The generated starter project contains a <code>content/</code> directory, a shared <code>presentation/page.html</code> template, and a short README.</p>

<h2 id="writing-content">Writing content</h2>
<p>Pages are Markdown files with TOML front matter between <code>+++</code> delimiters. The <code>title</code> attribute is required.</p>
<pre>+++
title = "A page title"
+++

# A page title

Write the page in Markdown.</pre>
<p>Raymatic renders each content file as a static page using the shared presentation template. Assets are copied, image dimensions are detected, and an <code>assets-manifest.json</code> file describes published assets.</p>

<h2>Presentation</h2>
<p>Edit <code>presentation/page.html</code> to control the document shell. The template receives <code>{{ title }}</code>, rendered <code>{{ body }}</code>, site identity, SEO metadata, navigation, and publication metadata. Plain HTML and CSS are the supported presentation boundary.</p>

<h2>Local development</h2>
<p><code>ray dev</code> serves the latest valid preview at <code>127.0.0.1:3000</code> (with fallback ports), watches content, presentation, and assets, and classifies the dependency that triggered each rebuild. An invalid edit leaves the last valid preview running; a later fix recovers automatically.</p>

<h2>Validation and diagnostics</h2>
<p>Run <code>ray check</code> before building. Diagnostics are structured and source-aware. They can identify malformed front matter, missing titles, invalid dates, missing assets, empty image alt text, template failures, route collisions, and broken internal references.</p>

<h2>Building</h2>
<p>Run <code>ray build</code> to validate and produce static output in <code>output/</code>. Output is staged and replaced only after a successful evaluation, so failed validation does not commit an invalid production tree.</p>

<h2>Project structure</h2>
<pre>my-site/
├── content/
├── presentation/
├── assets/
├── site.toml             optional site identity and base URL
├── README.md
└── output/              generated by ray build</pre>

<h2>Generated publication</h2>
<p>A successful build produces pages, archive and taxonomy views, RSS, Atom, sitemap, robots metadata, copied assets, and <code>assets-manifest.json</code>. Draft content is validated but excluded from public output.</p>
